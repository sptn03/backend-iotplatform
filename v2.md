# IoT Platform — Plan v3 (Final, sẵn sàng implement)

Plan cuối cho nền tảng IoT stack **Expo (bare) + Express + MySQL + Sequelize + EMQX MQTT broker tại `mqtt.nz03.com:1883`**, firmware generic cho ESP32/ESP8266 cấu hình pin động, API tại `https://iot.nz03.com`, admin EJS, auth token tự quản lý.

- App: thêm thiết bị, cấu hình pin động, điều khiển thủ công, xem realtime + history 60 ngày, nhận push khi device offline / OTA xong.
- Admin EJS: đăng nhập admin, dashboard users/devices online, upload firmware + trigger OTA rollout.
- Web flash firmware tại `https://iot.nz03.com/flash`.

## 4. Database schema (Sequelize, MVP)

```
users(id, email UNIQUE, password_hash, name, avatar_url, is_admin, created_at, updated_at)

user_tokens(
  id, user_id, token CHAR(64) UNIQUE,
  token_fcm VARCHAR(200) NULL,       -- Expo push token
  platform ENUM('ios','android','web') NULL,
  device_name VARCHAR(100) NULL,
  active TINYINT(1) DEFAULT 1,
  last_used_at DATETIME,
  expires_at DATETIME NULL,
  created_at
)

rooms(id, user_id, name, icon, sort_order, created_at)

devices(
  id CHAR(32) PK,                    -- deviceId hex 16 byte
  user_id FK, room_id FK NULL,
  name VARCHAR(100),
  model ENUM('esp32','esp8266'),
  chip_id VARCHAR(32), mac CHAR(12),
  fw_version VARCHAR(20), hw_version VARCHAR(20),
  secret CHAR(64),                   -- deviceSecret hex 32 byte
  online TINYINT(1) DEFAULT 0,
  last_seen_at DATETIME,
  settings_json JSON,                -- { notify_offline:true, ... }
  created_at, updated_at
)

device_pins(
  id BIGINT PK, device_id FK,
  pin_id VARCHAR(16),                -- "p1", "p2"
  gpio TINYINT, role VARCHAR(32), name VARCHAR(100),
  options_json JSON,
  current_value JSON NULL,
  updated_at,
  UNIQUE(device_id, pin_id)
)

device_state(device_id PK, state_json JSON, updated_at)

telemetry_raw(
  id BIGINT PK, device_id, pin_id VARCHAR(16), metric VARCHAR(32),
  value DOUBLE, ts DATETIME,
  INDEX(device_id, pin_id, ts)
)  -- sau 7 ngày rollup xong → xóa

telemetry_1m(device_id, pin_id, metric, ts_min, avg, min, max,
             PRIMARY KEY(device_id, pin_id, metric, ts_min))

telemetry_1h(device_id, pin_id, metric, ts_hour, avg, min, max,
             PRIMARY KEY(device_id, pin_id, metric, ts_hour))

events(id BIGINT PK, device_id, pin_id VARCHAR(16) NULL,
       type VARCHAR(32), payload_json JSON, ts DATETIME,
       INDEX(device_id, ts))

notifications(id, user_id, device_id NULL, title, body, data_json,
              read_at NULL, created_at, INDEX(user_id, created_at))

firmware(id, model, version, url, md5 CHAR(32), size, changelog, created_at)

ota_jobs(id, device_id, firmware_id, status ENUM('pending','running','success','failed'),
         requested_at, completed_at, error, INDEX(device_id))

audit_logs(id, user_id, action VARCHAR(64), target VARCHAR(100),
           ip VARCHAR(45), ts, INDEX(user_id, ts))
```

**Retention cron (mỗi ngày lúc 03:00)**:
- Xóa `telemetry_raw WHERE ts < NOW()-7d` (đã rollup vào 1m/1h).
- Xóa `telemetry_1m / 1h / events / notifications / audit_logs WHERE ts < NOW()-60d`.

## 5. MQTT topics & payload

```
nz03/d/{deviceId}/online      device→* retained LWT  "1" | "0"
nz03/d/{deviceId}/state       device→* retained       { pins: { p1: value, ... }, fw, ... }
nz03/d/{deviceId}/cfg         device→* retained       { pins: [ {pinId,gpio,role,name,options}, ... ] }
nz03/d/{deviceId}/telemetry   device→*                { pinId, metric, value, ts }
nz03/d/{deviceId}/event       device→*                { type, pinId?, payload, ts }
nz03/d/{deviceId}/ack         device→*                { reqId, ok, error? }
nz03/d/{deviceId}/cmd         app/backend→device      { reqId, ts, sig, op, data }
nz03/d/{deviceId}/ota         backend→device          { reqId, ts, sig, url, md5, version }
```

### Lệnh `op` hỗ trợ
- `set_pin` `{ pinId, value }`
- `config_pin` `{ pinId, gpio, role, name, options }`
- `delete_pin` `{ pinId }`
- `rename_pin` `{ pinId, name }`
- `read_pin` `{ pinId }` (ép publish state ngay)
- `reboot`
- `factory_reset`
- `set_wifi` `{ ssid, pass }` (đổi Wi-Fi từ xa, dùng thận trọng)

### HMAC
```
sig = HMAC_SHA256(deviceSecret, `${reqId}|${ts}|${op}|${stableJson(data)}`).toString('hex')
```
Firmware: reject nếu `|now - ts| > 60` hoặc sig sai hoặc reqId đã thấy (LRU 32).

## 6. Firmware — pin roles (MVP)

| Role | ESP32 GPIO khuyến nghị | ESP8266 GPIO khuyến nghị | Option |
|---|---|---|---|
| `digital_output` | 2,4,5,12-19,21-23,25-27 | 4,5,12,13,14,15,16 | `inverted`, `default` |
| `digital_input` | như trên + 34-39 (input only) | như trên | `pull`, `debounce_ms`, `emit_on` |
| `pwm_output` | bất kỳ GPIO output (LEDC) | 4,5,12,13,14,15 (analogWrite) | `freq`, `resolution`, `default_duty` |
| `analog_input` | 32-39 (ADC1) | A0 | `interval_ms`, `scale`, `offset` |
| `dht` | bất kỳ GPIO I/O | 4,5,12-14 | `type` (DHT11/22), `interval_s` |
| `ds18b20` | bất kỳ GPIO I/O | 4,5,12-14 | `interval_s` |
| `i2c_device` | SDA/SCL cấu hình | GPIO 4,5 mặc định | `addr`, `driver` (bme280/oled/lcd) |
| `uart_device` | UART1/2 | Serial1 (chỉ TX GPIO2) | `baud`, `driver` (pzem004t) |
| `ir_tx` / `ir_rx` | bất kỳ | 4,5,12-14 | `carrier_freq`, bộ mã đã học |
| `rf_tx` / `rf_rx` | bất kỳ | 4,5,12-14 | `protocol` |
| `neopixel` | bất kỳ output | 2,4,5,12-15 | `count`, `order` |

Firmware validate GPIO theo `model` trước khi `config_pin`.

4. Background → disconnect. Foreground → reconnect, đọc retained state/cfg/online.
5. Push: đăng ký `expo-notifications` token → `POST /api/me/push-token`.

## 9. Firmware bootstrap (ESP32/ESP8266)

```
setup():
  load NVS config
  if (!wifi_config) → start AP open "NZ03-<chipId>" + HTTP /provision
  else:
    connect WiFi
    if fail 30s → fallback AP
    connect MQTT (LWT online=0 retained)
    publish online=1 retained
    publish cfg retained (từ NVS)
    publish state retained (đọc pins)
    subscribe nz03/d/{id}/cmd, /ota

loop():
  pin manager tick (sample DHT/ADC theo interval, debounce input)
  heartbeat 30s (publish state diff)
  mqtt loop
  ota check flag
```

**Register flow (firmware)**:
```
POST https://iot.nz03.com/api/devices/register
Body: { claimCode, chipId, mac, model, fwVersion }
→ { deviceId, secret, mqttHost, mqttPort }
Lưu vào NVS, connect MQTT với clientId = deviceId
```

## 10. Worker backend (mqttIngest)

```
connect broker, subscribe "nz03/d/+/+"
on message(topic, payload):
  match topic:
    .../online       → update devices.online + last_seen_at, push notify nếu offline>5m
    .../state        → update device_state + device_pins.current_value
    .../cfg          → upsert device_pins từ cfg
    .../telemetry    → insert telemetry_raw + buffer rollup 1m
    .../event        → insert events, emit push nếu critical
    .../ack          → update ota_jobs / command_log
    other            → ignore

cron every 1m: flush telemetry_1m buffer → DB
cron every 1h: rollup 1m → 1h
cron 03:00:    retention 60 ngày + delete raw >7d
cron 30s:      check devices online heartbeat timeout
```
